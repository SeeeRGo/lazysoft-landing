# Портфолио + админка для Sprinthost

Отдельная PHP/MySQL-версия автономного сайта. Node.js, VPS, Convex, Composer и фоновые процессы не нужны. Внешний вид и интерфейс редактора берутся из `standalone/portfolio/public` при упаковке, поэтому две копии разметки не расходятся.

## Перед установкой

Бесплатный тариф не гарантирует доступность всех функций обычного хостинга. В конкретном аккаунте проверьте:

- PHP **8.1 или новее**, расширение **pdo_mysql**, MySQL 5.7/8 или MariaDB с InnoDB.
- Базу MySQL можно создать в панели и открыть через phpMyAdmin.
- HTTPS работает на выбранном домене, в том числе техническом. Админка без HTTPS недопустима.
- `memory_limit` минимум 256M, `post_max_size` минимум 16M, `max_execution_time` минимум 60 секунд. Для большого первоначального экспорта память/время могут потребоваться больше.
- MySQL `max_allowed_packet` минимум 16 МБ; дисковая квота учитывает базу и загруженные файлы.
- PHP читает каталог `private` рядом с `public_html`. Он должен находиться **вне корня сайта**.

В пакет включён `.user.ini` с этими лимитами и выключенным показом PHP-ошибок посетителям. Некоторые режимы PHP не читают этот файл: проверьте эффективные настройки в панели и при необходимости задайте их там. Применение `.user.ini` может занять несколько минут. Веб-сервер должен запрещать скачивание скрытых файлов, включая `.user.ini`.

Если какой-либо пункт недоступен на бесплатном тарифе, не загружайте секреты и не отключайте защиту: потребуется другой тариф/хостинг. Наличие Node.js на платном тарифе не имеет значения для этого пакета.

Официальные источники: [бесплатный тариф](https://free.sprinthost.ru/), [настройки сервера](https://help.sprinthost.ru/faq/server-settings), [PHP](https://help.sprinthost.ru/faq/php), [перенос сайта](https://help.sprinthost.ru/important/move).

## Подготовка пакета разработчиком

Из корня репозитория на Node.js 24:

```sh
node scripts/package-portfolio-sprinthost.mjs /ABSOLUTE/SNAPSHOT/data
```

Скрипт читает существующий `portfolio.sqlite` в транзакции, копирует контент, все файлы и историю. Старые сессии, ключи, настройки облака и Convex не копируются. Новый случайный ключ лежит в `INSTALL-KEY.txt`; не публикуйте его и сам архив. Источник не изменяется. После упаковки Node.js больше не нужен.

## Установка без SSH

1. Создайте аккаунт Sprinthost, сайт и отдельную пустую БД. Не используйте БД другого проекта. Запишите адрес сервера БД, имя, пользователя и пароль из панели.
2. Скачайте архив, распакуйте локально. Сохраните `INSTALL-KEY.txt` в менеджере паролей. В `private/config.php` заполните реквизиты БД и `origin`: например `https://f123456.xsph.ru` — без слеша в конце. Сгенерированный `setup_key_hash` не меняйте.
3. Включите сертификат и принудительный HTTPS через панель Sprinthost. Наш `.htaccess` также перенаправляет HTTP. Nginx может отдавать статику, минуя Apache, поэтому HTTPS должен быть включён именно для всего сайта в панели.
4. Через phpMyAdmin выберите пустую БД и импортируйте `schema.sql`. Все таблицы имеют префикс `pf_`, должны использовать InnoDB. Повторно импортировать схему в существующий сайт нельзя.
5. Через SFTP или файловый менеджер загрузите содержимое `public_html` в корень сайта, включая скрытый `.htaccess`. До замены стартовых файлов сделайте их копию. Каталог `private` загрузите **рядом** с `public_html`, не внутрь него:

```text
domains/ВАШ-ДОМЕН/
├── private/
│   ├── app.php
│   ├── install.php
│   ├── config.php        ← доступ к БД, вне веб-корня
│   └── seed.json         ← переносимые работы, удалить после установки
└── public_html/
    ├── .htaccess
    ├── index.html
    ├── admin.html
    ├── api.php
    ├── asset.php
    ├── install.php
    └── остальные HTML/CSS/JS
```

6. Для `private` установите права 700, его файлов — 600, если PHP работает от вашего пользователя. Не устанавливайте 777. Архив, `schema.sql`, `INSTALL-KEY.txt`, тестовые файлы и README не загружайте в веб-корень.
7. Откройте `https://ВАШ-ДОМЕН/install.php`, введите новый ключ. Установка переносит данные в одной транзакции; при ошибке частичный импорт откатывается. После успеха удалите **public_html/install.php** и **private/seed.json**. Повторная установка дополнительно заблокирована в БД.
8. Откройте `https://ВАШ-ДОМЕН/admin.html`, войдите тем же ключом. При передаче клиенту замените ключ кнопкой в админке. Старый установочный ключ после ротации не даёт доступ и не может повторно установить сайт.

## Что проверить до переноса домена

- Главная, четыре раздела, мобильная версия: изображения и тексты загружаются из MySQL.
- Админка: вход, загрузка JPG/PNG/WebP, PDF, изменение текста, публикация и история.
- Открытие сайта в другом браузере показывает опубликованные изменения.
- История открывает старую версию в форме; для восстановления её нужно опубликовать.
- «Отозвать доступ» завершает сессии во всех браузерах. Новый ключ отменяет старый.
- Через 15 минут требуется новый вход; ключ не сохраняется в localStorage.
- `/private/config.php`, `/seed.json`, `/schema.sql`, `/.env` недоступны. Веб-корень строго `public_html`.
- HTTP перенаправляется в HTTPS и на страницах нет ошибок смешанного содержимого.

Все API вызываются через обычные `api.php`/`asset.php`: красивые URL, rewrite для API, Node и постоянно работающий процесс не требуются. Если вход возвращает 401 с правильным ключом, проверьте передачу заголовка Authorization в PHP; правило включено в `.htaccess`.

## Ограничения и резервные копии

Сессия 15 минут, ограничение входа 5/мин, чтения API 120/мин, изменений 60/мин, загрузок 10/мин. Лимиты общие для сайта и сохраняются в MySQL, а не зависят от подделываемого IP. Это базовая защита, не замена анти-DDoS провайдера.

Максимум 40 работ, 100 файлов, 100 МБ файлов суммарно и 8 МБ на файл. Удаление работы скрывает её, но не стирает файл: он может требоваться для истории. Загруженные файлы доступны посетителям по URL, это не хранилище приватных документов.

База содержит **всё изменяемое содержимое и файлы**. Регулярно экспортируйте все таблицы `pf_` в SQL через phpMyAdmin и храните копию вне хостинга. На время экспорта не редактируйте сайт; предпочтителен согласованный транзакционный дамп. Отдельно сохраняйте файлы сайта и приватный `config.php`. Дамп содержит хеши доступа/сессий — храните приватно. После восстановления очистите `pf_sessions` через phpMyAdmin и замените ключ из админки. Не импортируйте дамп поверх новых данных без копии текущей БД.

Если потеряли ключ: сгенерируйте новый 32-байтный случайный base64url-ключ и его SHA-256 локально, затем в phpMyAdmin в одной транзакции обновите `pf_settings.key_hash` (id=1) и удалите все строки `pf_sessions`. Изменение `setup_key_hash` в конфиге само по себе доступ не восстанавливает.

Sprinthost Free требует входа в панель хотя бы раз в 30 дней; техподдержка работоспособности сайта не включена. Домен оплачивается отдельно, если не используется технический. Текущая демоверсия в Яндекс Облаке остаётся независимой: изменения между двумя установками не синхронизируются.
