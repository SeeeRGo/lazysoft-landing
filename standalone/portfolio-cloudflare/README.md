# Сайт с админкой: Cloudflare Workers Free + D1 + KV

Страницы, админка и API работают в одном Worker. Тексты, история и сессии
хранятся в D1, изображения и PDF — в Workers KV. R2 не используется.
Достаточно Workers Free: подписка R2, Workers Paid и банковская карта для
этого комплекта не нужны. Домен workers.dev и HTTPS входят в размещение.

## Установка

Установите Node.js LTS и распакуйте архив. На Windows запустите
`install-cloudflare.cmd`, на macOS / Linux — `sh install-cloudflare.sh`.
Установщик создаст D1 и KV, перенесёт содержимое и покажет адрес workers.dev.

При первом входе используется `npx wrangler login --device`: сверьте код
в браузере и Терминале, выберите нужный аккаунт и разрешите доступ.
Не закрывайте Терминал до завершения. Если браузер не открылся, скопируйте
свежую ссылку из Терминала. Этот способ не использует localhost.
При истечении кода повторите запуск. Проверка входа: `npx wrangler whoami`.
Если доступно несколько аккаунтов, задайте `CLOUDFLARE_ACCOUNT_ID` для нужного.

Админка: адрес сайта + `/admin.html`. Ключ находится в `INSTALL-KEY.txt`.
Не публикуйте персональный ZIP, ключ и `seed/seed.sql`.

## Бесплатные ограничения

KV Free: 1 ГБ на аккаунт, 100 000 чтений и 1000 записей в сутки; квоты
разделяются с другими проектами аккаунта. При исчерпании квоты операции
возвращают ошибку до её сброса. Workers и D1 имеют отдельные квоты.

В приложении: до 40 работ, 100 файлов / 100 МБ суммарно, до 8 МБ на файл
(JPG, PNG, WebP, PDF). Удаление работы не удаляет файл из хранилища:
он может использоваться в истории. Полная резервная копия с файлами доступна
до 40 файлов и 32 МБ суммарно. При превышении сохраняйте файлы отдельно.

Новые файлы в KV могут появляться у посетителей около минуты или дольше.
Подождите и обновите страницу. Если какой-либо файл временно недоступен,
резервная копия не выдаётся как полная — повторите её создание позже.

## Повторный запуск и переход с R2

Не удаляйте `installation-state.json`: установщик продолжает загрузку с
оставшегося файла и сохраняет существующую базу. Старое `assetsUploaded`
для R2 не считается загрузкой в KV. При смене аккаунта старый прогресс
сохраняется в `installation-state.json.previous-*`, новый аккаунт получает
собственные ресурсы. Содержимое между аккаунтами автоматически не копируется:
новая установка получает исходные данные архива.

Для перехода опубликованного сайта нужны все его файлы в `seed/assets`
и актуальный `seed/assets.json`. Если в D1 появились файлы, которых нет
в архиве, установщик остановится до публикации. Подготовьте актуальный комплект.
Старое R2-хранилище и его подписка автоматически не удаляются и не отменяются.
