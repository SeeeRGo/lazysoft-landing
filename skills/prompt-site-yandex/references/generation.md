# Контракт генератора Lazysoft

Сгенерируй только запрошенный `versions/N`. На доработке сохрани содержание
последней версии и учти новое сообщение, остальные версии не доступны для записи.
Структурированный ответ: `{"title":"Название","variants":[{"id":"N","title":"Название версии"}]}`.

## Файлы

- `/workspace/README.md`: запуск, функции, технические ограничения и незавершённые интеграции.
- `versions/N/index.html`, стили, JS, локальные изображения.
- `versions/N/cms-schema.json` и `cms-content.json` по контракту ниже.
- Дизайн и каталог используют общий модуль `cms.js`.

Worker добавляет проверенные `admin.html`, `cms-admin.js`, `cms.js`,
`cms-model.mjs`, `cms-config.js`, `cms-admin.css`. Не заменяй эти файлы своей
упрощённой админкой. Не сохраняй копию каталога в отдельном массиве или localStorage.

## Структура данных

`cms-schema.json`:
```json
{"format":"lazysoft-cms-v1","fields":[{"key":"heading","label":"Заголовок","type":"text","required":true}],"collections":[{"key":"products","label":"Товары","fields":[{"key":"name","label":"Название","type":"text","required":true},{"key":"price","label":"Цена","type":"number"},{"key":"image","label":"Фото","type":"image"},{"key":"description","label":"Описание","type":"textarea"}]}]}
```

`cms-content.json`:
```json
{"values":{"heading":"Магазин инструментов"},"items":{"products":[{"id":"drill","name":"Дрель","price":5000,"image":"images/drill.svg","description":"Демонстрационный товар"}]}}
```

Типы полей: text, textarea, number, image, url. Ключи латиницей с дефисами/
подчёркиваниями, начинаются с буквы. Идентификаторы записей уникальны внутри
каталога. Все объявленные поля присутствуют: строки или числа; пустое изображение
— пустая строка. Начальные изображения локальные, не внешние URL. Добавь редактируемые
поля для всех важных текстов, контактов, цен и изображений. Каталог может быть пустым
или содержать больше исходного количества записей. Поиск, фильтры и корзина должны
использовать текущие данные, не захардкоженные шесть товаров.

Каждая коллекция выводится на главной странице, либо указывает `page` — относительный
путь к её HTML-странице (например `catalog.html`). Все страницы дают переход в админку.

Подключение на каждой публичной странице:
```html
<script src="cms-config.js"></script>
<script type="module" src="app.js"></script>
```
```js
import {CMS} from './cms.js';
const {content} = await CMS.load();
// Рендер из content.values и content.items. Пользовательские строки — textContent.
// Экранируй текст/атрибуты при создании HTML. Изображения — поля image.
```
Покажи понятную ошибку загрузки вместо пустого экрана. Не делай собственный сервер,
файлы авторизации или запросы к внешним API. Серверные пакеты собирает worker из
проверенного CMS-модуля, сохраняя этот же дизайн и данные.

## Проверки

Проверь поиск/фильтры/корзину, если они нужны идее, ссылки, новые/удалённые записи,
замену изображения, пустой каталог, мобильную ширину. Worker отдельно проверяет
CMS в браузере: добавляет запись и изображение в админке и ищет новую запись на
публичной странице. Если данные отрисованы из фиксированного массива, выпуск не пройдёт.

Демо в Яндекс Object Storage явно помечено как демонстрация. Клиентские пакеты
содержат отдельный сервер, ключ администратора и инструкцию установки. Внешние
интеграции, не реализованные и не проверенные, перечисляются в README; не обещай
приём реальных оплат/заказов через декоративную кнопку.
