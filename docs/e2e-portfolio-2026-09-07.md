- Локальный сервер принял заявку через `/api/mvp-request`.

  и серверный `REQUEST_AUTOMATION_ALLOWED_REQUEST_ID`, без перехода к чужим задачам.
- Сохранённая ChatGPT-авторизация работает: Codex ответил в контейнере.

## Найдено

1. В `docker run` отсутствовал `-i`: stdin с заданием не передавался в контейнер.
   Исправлено в `automation/worker.mjs`.
2. Независимая проверка записи одного файла через Codex воспроизвела ошибку
   `bwrap: No permissions to create a new namespace`.
   Текущие ограничения Docker несовместимы с внутренней песочницей Codex.
   Защита не отключалась; настройки хоста не менялись.
3. ID, начинающийся с `#`, в тестовом env-файле должен быть в кавычках.

## Продолжение после разрешения пользователя

Пользователь разрешил изменить изоляцию отдельного тестового контейнера.
`automation/test-isolation.mjs` включает исключение только при трёх совпадениях:
`CODEX_TEST_NESTED_SANDBOX=true`, dev URL `notable-buffalo-804` и
`REQUEST_WORKER_REQUEST_ID="#a3a63e38"`. Без opt-in настройки не меняются;
другая заявка или deployment отклоняются до claim.

Для этого контейнера используются `seccomp=unconfined` и
`apparmor=unconfined`, чтобы разрешить создание внутренней песочницы.
Codex продолжает работать в `workspace-write`, от непривилегированного
пользователя, с `cap-drop=ALL`, `no-new-privileges`, read-only корнем и
лимитами ресурсов. Docker socket, исходный репозиторий и облачные ключи
в контейнер не монтируются. Настройки хоста не менялись.
Проверка записи: `/workspace/check.txt` создан, запись в `/usr/local` отклонена.
Основание: https://learn.chatgpt.com/docs/security

Первый проход после снятия блокировки выявил потерю управляющего процесса
при завершении терминальной сессии. Контейнер не перезапускался: heartbeat
и публикацию готовых файлов восстановил отдельный локальный recovery-процесс.
Worker теперь обрабатывает SIGTERM/SIGINT с остановкой своего контейнера.
Правки запущены штатным worker в отдельном процессе, не зависящем от сессии.

Генератор положил Markdown-ТЗ в каталог демо. Markdown добавлен в явный
allowlist артефактов; ограничения размера, числа файлов и запрет symlink
сохранены. Это покрыто тестом.

Ограничения проверки: это dev, а не production. Проверена доставка только в

полностью автономной устойчивости к падениям. Штатный полный путь обработки
артефактов проверен на ревизии. Таймер и production-обработка не включались.

По завершении `REQUEST_AUTOMATION_ENABLED=false` в dev.
Автоматический таймер не включён. Тестовая заявка сохранена для продолжения;
создавать её повторно не нужно. Секретная ссылка хранится только в локальном
игнорируемом `.local/e2e-request.json`.

Тестовый opt-in в `.local/e2e-worker.env` выключен после завершения.

исключение для одной dev-заявки не переносить на все заявки.
