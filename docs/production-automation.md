## Изоляция

Модель получает только нормализованный бриф, CMS-контракт и файлы текущей версии. Ключ RouterAI используется только в HTTP-заголовке executor и проверяется на отсутствие в контексте и ответе. Облачные ключи, bot token и контакты клиента модели не передаются.

## Секреты и запуск

Convex хранит только URL executor и общий dispatch/worker secret. RouterAI и Object Storage secrets находятся в окружении executor. Не печатайте их содержимое и не сохраняйте на рабочем компьютере.

Initial и revision jobs сразу планируют Convex action. При недоступности executor Convex сохраняет job в `queued` и повторяет dispatch с backoff. Включение регулируется Convex env `REQUEST_AUTOMATION_ENABLED`; GitHub schedule отсутствует.

## Доставка

Сначала создаётся одна версия сайта по исходной идее. Пользователь может
отправить ещё два сообщения с доработками: каждое создаёт новую версию на основе
последней готовой. Предыдущие ссылки и отдельные ZIP сохраняются. Купить можно
любую готовую версию, начиная с первой; покупка доступна и во время подготовки
следующей версии. Уведомление владельцу
приходит в Telegram. Для доставки клиенту в Telegram нужен запуск
`@lazysoft_mvp_idea_bot` кнопкой на странице заявки; одного username недостаточно.
Webhook направляется на production Convex с отдельным секретом.
Клиентам, оставившим email/MAX, результат пока передаётся владельцем вручную:
SMTP и MAX bot token не настроены. Страница заявки доступна независимо от канала.
ЮКасса выключена: кнопка исходников отправляет уведомление, оплата и передача
обсуждаются вручную. Оплата не выставляется автоматически.

В стандартном предложении исходники выбранной версии стоят 5 000 ₽, помощь
с установкой — ещё 3 000 ₽. Для следующего ценового теста предусмотрен бюджетный
вариант: 3 000 ₽ и 2 000 ₽ соответственно. Одновременно клиент видит только один
вариант цены. Он задаётся GitHub Actions variable `PUBLIC_SITE_OFFER_VARIANT`:
`standard` (или пустое значение) — стандартная цена, `budget` — бюджетная.
После изменения переменной требуется новый production-деплой.

В комплект входят выбранная версия сайта, админка, архив исходников и инструкции:
`/guides/cloudflare-free.pdf` и `/guides/hostiman-options.pdf`. Нажатие на покупку
передаёт в Telegram номер версии, выбранный хостинг, состав комплекта и цену.

## Обновление: только демо

Генерация PDF и ТЗ исключена из новых задач и правок. На одну задачу модель
создаёт ровно одну версию в `versions/<targetDemoId>` с `index.html`, `admin.html`
и `README.md`. При доработке в рабочую область модели копируется только последняя
готовая версия под новым номером; прежние версии остаются вне её рабочей области.
Worker самостоятельно собирает общий архив истории и отдельный архив новой версии.
В публичный бакет загружается только новая версия под новым случайным префиксом.

Новые заявки имеют `revisionCount: 0`; счётчик увеличивается при принятии сообщения,
а не при повторной попытке worker. Максимум — два сообщения, один активный job.
`targetDemoId` и `baseDemoId` закреплены за job; изменение выбора для покупки
не меняет основу уже запрошенной доработки. После ошибки старые варианты остаются
доступны для покупки. Дополнительное сообщение после ошибки расходует оставшийся
лимит; повторные попытки текущего job не расходуют его.

Worker использует протокол `2`. Backend не отдаёт задачи старому worker без этого
номера. Обновлять frontend, API, Convex и GitHub worker нужно согласованно.
Для старых уже готовых заявок без `revisionCount` сохранён прежний лимит правок;
готовые сайты и оплаченные материалы не удаляются. Старые PDF доступны в истории.
Автоматическая оплата по-прежнему выключена: выбор версии и комплекта передаётся
владельцу для ручного согласования оплаты и передачи.

## Остановка и откат

```sh
npx convex env set REQUEST_AUTOMATION_ENABLED false --prod
```

Эти действия останавливают новые задачи, но не отзывают уже готовые результаты.
Для прерывания текущей задачи остановите её в hosted executor; выключение `REQUEST_AUTOMATION_ENABLED` блокирует новые dispatch.

`Deploy to Yandex Cloud`; данные Convex не удалять и dev поверх prod не импортировать.
