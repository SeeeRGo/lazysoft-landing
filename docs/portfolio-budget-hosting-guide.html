Подготовка · до оплаты

1. Проверьте хостинг
и получите комплект

Создайте аккаунт на своё имя

Откройте виртуальный хостинг Beget, выберите Blog и тестовый период, если он доступен. Аккаунт и домен должны принадлежать владельцу сайта, а не разработчику. Включите дополнительную защиту входа, если она предлагается.

Отправьте поддержке этот текст

Хочу разместить небольшой сайт с админкой на виртуальном хостинге Blog, без VPS. Нужны Ubuntu 22.04, официальный Node.js 24.15.0 x64 с модулем node:sqlite и Apache Passenger. База SQLite WAL с изображениями хранится в приватной папке вне public_html. Подтвердите постоянство файлов после перезапусков, поддержку блокировок SQLite на диске и доступ Passenger к каталогу приложения. Можно ли это проверить в тестовый период без доплат? Нужна помощь с точкой входа passenger.cjs и DocumentRoot app/webroot.

Если ответ отрицательный или предлагается только старый Node — не продолжайте оплату. Попросите подходящий сервер/окружение. Наличие слова «Node.js» на сайте провайдера само по себе недостаточно.

Что получить от разработчика

  • Свежий архив portfolio.tar.gz: сайт, админка, backend, база с работами, изображения и история.
  • Подтверждение, на какой момент актуальны данные. На время финального переноса не редактируйте старую админку.
  • Доступ к своему домену/DNS. Для пробного запуска — технический домен с HTTPS, если хостинг его предоставляет.
Не переносите секреты старой инфраструктуры.

В архиве не должно быть .env, ключей Яндекс Облака, авторизации Codex или старого ключа админки. Новый ключ создаётся на вашем хостинге. База и архив не должны лежать в публичной папке сайта.

Что уже проверено, а что нет

Автономная версия работает на отдельной VM Яндекс Облака: проверены HTTPS, админка, файлы и сохранность после перезагрузки. Размещение на Beget ещё не проверено на реальном аккаунте; эта инструкция опирается на их документацию и подготовленную совместимую точку входа.

Файлы и безопасные каталоги

2. Загрузите сайт

Создайте в панели Beget отдельный новый сайт. Загрузите архив файловым менеджером или по SFTP в приватный каталог этого сайта, рядом с public_html, а не внутрь него.

Распакуйте архив. Полученную папку portfolio переименуйте в app. Итоговая структура должна быть такой:

SITE/
  .htaccess               ← настройка Passenger
  public_html → app/webroot
  app/
    server.mjs
    passenger.cjs
    hosting.json           ← создадите из примера
    public/                ← страницы, CSS и JavaScript
    webroot/               ← только служебный .htaccess
    data/
      portfolio.sqlite     ← контент, файлы и история
    tmp/
      restart.txt
Критично: public_html должен указывать на app/webroot, а не на app, app/public или app/data. В нашем варианте файлы и защитные заголовки отдаёт приложение. Не открывайте базу браузеру ради устранения ошибки доступа.

Настройте адрес

В редакторе файлов скопируйте содержимое hosting.example.json в новый hosting.json и подставьте адрес своего сайта:

{
  "publicOrigin": "https://portfolio.example.com"
}

portfolio.example.com — пример, его нужно заменить. Без слеша в конце и без подкаталога. При смене технического домена на свой обновите этот файл и перезапустите приложение.

Права доступа

  • Папка app/data: 700.
  • Файл portfolio.sqlite и файлы ключей: 600.
  • Владелец — пользователь, от которого хостинг запускает приложение.

Права выставляются через файловый менеджер. Не используйте 777. Если Passenger не видит приватный каталог, обратитесь в поддержку с его точным путём.

Все данные остаются у владельца сайта3 / 7
Однократная техническая настройка

3. Установите Node.js

Этот этап можно передать разработчику или поддержке. Обычному владельцу после установки терминал для редактирования портфолио не понадобится.

Войдите в нужное окружение

Откройте SSH-терминал из панели либо подключитесь по адресу, указанному в аккаунте. Затем войдите во внутреннее окружение Beget:

ssh localhost -p 222
cat /etc/os-release

Нужна Ubuntu 22.04. На старом окружении 18.04 остановитесь и попросите поддержку сменить сервер. Следующие команды выполняются внутри этого окружения.

Установите отдельную копию Node для портфолио

Команды ниже создают каталог в домашней папке аккаунта. Если .local/portfolio-node уже занят другим приложением, не перезаписывайте его.

cd
mkdir -p .local/portfolio-node
cd .local/portfolio-node
curl -fL -O https://nodejs.org/dist/v24.15.0/node-v24.15.0-linux-x64.tar.xz
tar -xJf node-v24.15.0-linux-x64.tar.xz --strip-components=1
./bin/node -v
pwd

Ожидаемая версия: v24.15.0. Запишите полный путь, который покажет pwd. Путь к исполняемому файлу — эта строка плюс /bin/node.

Изоляция сайтов Beget.

По их инструкции веб-серверу нужно разрешить доступ к каталогу установленного Node через настройки изоляции/общего доступа. Попросите поддержку открыть только необходимый каталог Node, не app/data и не всю домашнюю папку.

Что не требуется

Не устанавливайте PM2, Docker daemon, MySQL или PostgreSQL. Не нужен npm install: этот комплект использует встроенные модули Node. Не нужно держать SSH-терминал открытым — процесс будет запускать Passenger.

Команды ориентированы на версию, указанную в документации Beget на дату проверки. Новую версию Node сначала проверяют тестами, затем обновляют рабочий сайт. Официальная инструкция по Node.js.

Запуск приложения

4. Настройте Passenger

В каталоге SITE, рядом с public_html, создайте .htaccess по образцу app/beget.htaccess.example. Все пути в примере замените на реальные из своего аккаунта:

PassengerEnabled on
PassengerNodejs /home/u/ACCOUNT/.local/portfolio-node/bin/node
PassengerAppRoot /home/u/ACCOUNT/SITE/app
PassengerAppType node
PassengerStartupFile passenger.cjs
PassengerAppEnv production

ACCOUNT, SITE и начальная часть /home/u/… — не готовые значения. Точный путь можно получить командой pwd в нужном каталоге. Запускать надо passenger.cjs, не server.mjs.

Свяжите публичную папку с webroot

Попросите поддержку настроить public_html → app/webroot. Либо, только для нового пустого сайта, из каталога SITE сохраните исходную папку и создайте ссылку:

mv public_html public_html.before-portfolio
ln -s app/webroot public_html

Не выполняйте это на существующем рабочем сайте или если резервное имя уже занято. Не удаляйте старую папку: она нужна для отката.

Проверьте окружение и создайте новый ключ

Перейдите в app. Вместо NODE_BIN в каждой команде вставьте полный путь к установленному …/bin/node:

NODE_BIN check-hosting.mjs
NODE_BIN --test test.mjs
NODE_BIN manage.mjs reset-key
mkdir -p tmp
touch tmp/restart.txt

NODE_BIN здесь — обозначение для замены, не команда. Проверка окружения должна вывести PASS, тесты — 7 passed. Если нет, не продолжайте: передайте сообщение об ошибке разработчику.

Ключ входа: команда reset-key выводит путь к приватному текстовому файлу, а не пароль в логах. Откройте этот файл в приватном файловом менеджере и сохраните ключ в менеджере паролей. При повторном выполнении команды прежний ключ и все сессии перестанут работать.

Проверка и обслуживание

5. Подключите HTTPS
и проверьте результат

  1. Добавьте домен к сайту в панели. В текущем DNS настройте запись A на адрес, который показывает Beget. Проверьте, не осталось ли старого AAAA для этого же имени.
  2. Не меняйте MX и почтовые TXT-записи. Перевод всех NS к другому провайдеру без переноса зоны может сломать почту. Для сайта обычно достаточно изменить нужную A-запись.
  3. Дождитесь обновления DNS и включите бесплатный SSL в панели. До появления корректного HTTPS не вводите ключ админки.
  4. Откройте https://ВАШ-ДОМЕН/health: ожидается {"ok":true}. Проверьте главную и четыре раздела портфолио.
  5. Откройте https://ВАШ-ДОМЕН/admin.html, войдите новым ключом. Загрузите тестовую работу и опубликуйте. Затем обновите app/tmp/restart.txt и убедитесь, что работа осталась. Уберите тестовую работу через админку.

Короткий контрольный список

  • С телефона и компьютера нет обрезанного текста и горизонтальной прокрутки.
  • Изображение открывается, контакты ведут куда нужно.
  • /data/portfolio.sqlite, /hosting.json и /server.mjs возвращают 404, а не скачиваются.
  • После перезапуска сайт работает, контент и файлы сохранились.
  • Оплата за год производится только после успешных проверок.

Резервное копирование без платной базы

Из каталога app запускайте тем же полным путём Node:

NODE_BIN manage.mjs backup

Команда создаёт новую согласованную копию backup-….sqlite в data и выводит путь. Скачивайте копию через приватный файловый менеджер после важных правок и перед обновлениями. Храните хотя бы одну копию вне хостинга.

При частых правках попросите настроить ежедневный Cron с полным путём к Node и скрипту. Ручная команда не удаляет старые копии: следите за местом. Не копируйте только рабочий portfolio.sqlite при запущенном приложении — часть данных может ещё находиться в WAL.

Как перестать платить за старое демо

После проверки нового сайта согласуйте с разработчиком отключение прежней VM Яндекс Облака и судьбу её диска, зарезервированного IP и резервных копий. Простая остановка VM не прекращает все расходы. Не удаляйте инфраструктуру до сохранения проверенной копии и подтверждения переноса.

Старое и новое демо не синхронизируются. После переезда редактируйте только новую админку. При последующих обновлениях кода не заменяйте папку data старой базой из архива.
